## F-1 最终回答双显（设计取舍，待真实反馈）

前缀流式 + `====` 框内重显。流的最终性只有结束后才知道，扣住不发会失去慢网络下的活性反馈。长答案（>50 行）重复量大。若试用反馈嫌吵，可改为"最终轮检测到后抑制前缀流"——但那要在流开始前就知道没有 tool call，做不到；可行折中是框内不重显、只在流前加分隔线。

## F-2 叙述前缀污染代码块视觉

`| ` 前缀对 markdown 代码块行同样生效（样例中 ``` 与代码行均带前缀）。无 ANSI/VT 约束下无法做行内样式；可考虑检测 ``` 状态切换前缀（例如代码块内用 `  ` 两空格），本轮未做。
