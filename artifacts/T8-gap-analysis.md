# T8：对标 Claude Code 的能力差距评估

> 纯调研报告，零代码。每项三选一判断：**建议做** / **暂不做** / **不做**。
> 基于本项目实际约束（内网 DeepSeek / IT 用户 / Win7 / 单 EXE / 禁外部服务 / Go 1.20）。

## 「建议做」项优先级排序

| 优先级 | 项目 | 理由 | 工作量 |
|---|---|---|---|
| **P0** | #30 探索策略提示词优化 | R2 失败的直接原因；零代码改动；效果立竿见影 | 改 1 行提示词 |
| **P1** | #10 项目记忆（AGENT.md 扩展） | R2 失败的间接原因（无积累）；IT 用户最大痛点 | ~30 行代码 |
| **P2** | #1 ripgrep 集成（备选） | 当前规模够用，但项目增长后需要；技术已验证 | ~50 行（外部调用 rg.exe） |

## 如果只能再做三件事就交付内网试用

1. **探索策略提示词优化**（P0）：在系统提示词中加入"探索项目时，先用 ls 看顶层 1-2 层，然后用 grep 定位关键文件，选 3-5 个最有信息量的文件 read 深入，然后直接总结。不要逐目录遍历。"——这直接解决 R2 的 105 次 ls 问题，零代码。

2. **项目记忆**（P1）：任务完成时自动在 AGENT.md 末尾追加"## 近期改动\n- [日期] [任务描述] → [改动摘要]"。下次打开时模型直接看到之前做了什么，不需要从零探索。积累越多，效率越高。

3. **真实验证一轮**：找 2-3 个 IT 同事，在真实内网环境（不是测试 VM）各跑 3-5 个真实任务，收集失败形态和体验反馈。任何内部测试都无法替代真实用户的手感——尤其是"确认门烦不烦""agent.log 看不看""AGENT.md 写不写"这类只有真实使用才能回答的问题。
