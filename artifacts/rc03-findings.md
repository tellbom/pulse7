# RC0.3 findings

## 重大发现：python 无法在 Sandboxie 沙盒内执行

**现象**：S1/S2 的 shell 工具返回 `exitcode=-1`（无输出）。模型正确完成了代码修改，但验证时反复尝试运行 `python calc.py`（S1 尝试了 21 种方式），全部失败，消耗全部轮次。

**根因**：Python 3.8.1 安装在用户目录（`C:\Users\user\AppData\Local\Programs\Python\Python38\`），Sandboxie 沙盒无法执行该位置的程序。简单命令（echo、dir）可在沙盒内运行，但 python 不行——可能是 PATH 解析或 DLL 加载限制。

**证据**：
- 在沙盒外直接运行 `python calc.py` → `each pays: 30.0` ✅
- 在沙盒内运行 `python --version` → 超时/无输出 ❌
- S1 的实际文件修改（`people = 4`）是正确的 ✅
- S2 的实际文件修改（`def trim(s):`）是正确的 ✅

**影响**：Sandboxie 模式下，任何需要运行用户安装程序（python、dotnet 等）的验证都无法完成。JobObject 模式无此问题（正常文件系统访问）。

**修复方向**（本轮不做）：
1. Sandboxie 配置 `OpenPipePath=$:python.exe` 或类似程序例外
2. 或安装 python 到系统路径（C:\Python38）
3. 或在确认门后提供降级验证（沙盒外运行验证命令）
4. 或在 shell 工具描述中说明"沙盒内可能无法运行用户安装的程序"
