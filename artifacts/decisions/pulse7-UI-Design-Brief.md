## 1. 这是什么，给谁用

pulse7 是跑在 **Windows 7 SP1** 内网机器上的终端 AI 编程助手，单个 exe，模型跑在公司内网端点上。现在要给它做图形界面。

**用户**：公司内的 IT 与技术岗同事。会用命令行，但不是全职开发；手上多是老机器、老屏幕；平时的参照物是任务管理器、工单系统、机房面板，不是 VS Code，也不是聊天软件。

**界面要解决的问题**：agent 默认不问就干活（这是有意的产品决策），所以用户随时要能回答三个问题——

> **它刚才做了什么？现在在干什么？我能不能撤销？**

**界面不解决的问题**：让 agent 更聪明。不要设计任何"帮模型规划""让用户审批每一步"的东西。

## 2. 六条界面原则

这六条是产品哲学，翻译成界面规则。设计取舍时以此为准。

| 原则 | 界面含义 |
|---|---|
| **高自治** | 默认不打断。没有逐条确认弹窗，没有"确定要执行吗"。界面是仪表盘，不是审批流。 |
| **低摩擦** | 首次运行三步内能发出第一个任务。常用动作（引用文件、贴日志、中断）都在一步内。 |
| **强可见** | 凡是系统替用户做了处理——截断、压缩、放行、重试、降级、写到工作区外——都必须在界面上留痕。**可见不等于打断：留痕是记录条，不是弹窗。** |
| **低成本事实校验** | 用户想核实时必须能一路点到原始事实：文件路径可复制、命令原文可展开、工具结果可展开到完整内容。**默认折叠，展开只要一下。** |
| **错误可恢复** | 回滚、中断续跑、重试要在界面上明确可达，且回滚前必须回显具体目标（序号 + 时间 + commit 短哈希）。 |
| **不装作知道** | 估算值标为估算；等待要说清等了多久、在等什么；被截断要说清丢了多少。**禁止假进度条、禁止"处理中…"这种不含信息的占位。** |

## 3. 屏幕清单

按优先级排。时间不够就砍 P2，不要砍 P0。

### P0 —— 没有它产品跑不起来

**A. 首次运行向导（三步）**
同事双击**桌面快捷方式（目标为 `pulse7 serve`）**进入图形界面，没有配置、没有 key、不知道选哪个目录。**直接双击 exe 本体仍是 CLI 黑窗体——这不是错误，向导首屏要写清这一区别。**（启动路径已裁决：仅 `serve` 模式启动本地监听并打开页面；普通 CLI 行为保持不变。）
- 步骤 1：填端点地址 + 模型名 + API key → 一个「测试连接」按钮，就地显示结果（成功/失败原因）
- 步骤 2：选工作区目录（可浏览，显示最近使用过的）
- 步骤 3：开始
- 要有"跳过，我自己改配置文件"的出口，但不要做成默认路径

**B. 主工作台（默认态）**
三区：左侧会话/工作区（可折叠）、中间任务流、右侧常驻状态栏（第 4 节）。

**C. 任务流中的等待态**
内网端点慢是常态，一轮几十秒很正常。必须能区分：
- 在等模型第一个字（显示已等待时长）
- 模型在输出（文字流式出现）
- 工具在跑（显示是哪个工具、跑了多久）
- 已中断 / 已超时
**这四种状态长得必须不一样。** 只有一个转圈图标不合格。

**D. 任务结束摘要**
一次任务结束时的固定块，包含：结束形态（完成 / 需要你回答 / 触顶中止 / 出错中止 / 已中断）、总轮次、总耗时、本次执行的 shell 命令清单、**本次在工作区外写入的文件清单（附"不在 checkpoint 覆盖范围内、无法回滚"的说明）**、可回滚提示、留下来的后台/detached 进程清单。

**E. 连接失败与降级态**
端点连不上、token 失效、Job 受限模式（进程树控制未建立）。要说清发生了什么、影响什么、怎么办。降级模式必须**持续可见**，不能只在结束时提一句。

### P1 —— 第一批试用就会用到

**F. 工具调用展开态**：折叠时一行（工具名 + 参数摘要 + 耗时 + 成功/失败）；展开是完整结果，路径可复制。
**G. 后台任务面板**：task_id、命令、运行时长、输出大小、状态；能拉输出、能终止。**后台任务的价值就是脱离当前对话轮次，所以它必须常驻可见，不能埋在任务流里。**
**H. 检查点与回滚**：列表（序号、时间、commit、自动还是模型主动创建、涉及文件）；回滚确认必须回显目标。
**I. 设置**：配置分两层（全局 `%USERPROFILE%` / 项目 `.pulse7`），界面上要看得出当前生效值来自哪一层。**页面上可直接保存配置**（写入全局层并持久化生效），旁边配「测试连接」按钮（就地显示成功/失败原因）。**API key 只允许出现在全局，界面上不给项目级 key 的入口；key 保存后不回显明文。**

### P2 —— 有时间再画

**J. 权限确认请求**：默认档位是放行，这个界面平时不出现；只在用户主动切到严格/标准档位时才有。按低频设计，别为它牺牲主流程。
**K. Skills 面板**：列出当前可用的 skill（名称 + 描述 + 来源：项目级/个人级）。
**L. 空态**：新工作区、无会话、无后台任务、无检查点。空态是引导，不是道歉——写清下一步能做什么。

## 4. 四个常驻区域（**不能埋进任务流**）

右侧状态栏固定显示，任何时候都在：

1. **上下文余量** — 已用 / 预算 / 剩余百分比。**必须明确标注这是估算值**（端点大概率不回传真实用量）。接近阈值时提前变色，不要等触顶。
2. **后台任务** — 运行中的数量与状态，一眼看得到有没有东西还在跑（含输出截断标记：**截断了但进程还在跑，不是结束**）。
3. **进程概况** — 会话内进程数与告警阈值（超阈值变色提醒、不拦截）；**受限模式（restricted）状态常驻可见**——确定性清理未建立时用户随时能看到清理范围，不能只在结束时提一句；上次会话留下的 detached 进程历史以「未经核实」标注展示。
4. **当前可用 skills** — 有哪些、本轮用了哪个。

## 5. 事件 → 界面映射（**设计稿的组件命名请沿用左列**）

后端已定的事件名如下。**每个事件在界面上必须有归宿，不要自创事件，也不要漏。** 左列名称直接用作 Figma 组件名，便于后续联调。

| 事件 | 界面表现 |
|---|---|
| `session_init` | 顶部条：工作区路径、模型名、可用工具数、skills 数、上下文预算 |
| `assistant_delta` | 任务流中的模型文本，流式追加 |
| `assistant_attempt` | 流式重试：第几次尝试、start/complete/discard 三态；**discard 后上一次的残留文本必须从界面上消失**，不能拼在最终答案前面；连接断开未见 complete 的文本按不完整处理 |
| `tool_call` | 工具记录条出现，状态=进行中 |
| `tool_result` | 同一条更新为成功/失败 + 摘要，可展开完整结果；能力性拒绝（hard_link_impact_unknown）与权限不足要区分展示 |
| `permission_request` / `permission_response` | P2 屏 J，默认档位下不出现 |
| `context_state` | 常驻区 1 |
| `compaction` | 任务流中一条系统记录：触发原因、压缩前后用量、摘要可展开；**method=truncate 时附丢弃字节数与保留/丢弃的工具调用 ID 清单，可展开看丢了什么** |
| `skill_loaded` | 任务流中一条轻记录 + 常驻区 4 高亮 |
| `background_task`（启动/新输出/结束） | 常驻区 2 + 屏 G |
| `heartbeat` | 屏 C 的等待态，显示已等待时长 |
| `turn_result` | 屏 D，五种形态各自不同（完成 / 需要回答 / 触顶 / 出错 / 中断） |
| `outside_workspace_write` | 工作区外写入：发生时任务流一条记录（requested → resolved 路径），结束摘要里汇总 |
| `process` | 进程创建 / 结束 / 被终止各一条轻记录，供常驻区 3 与后台面板 |
| `process_mode` | 受限模式的进入与持续状态，常驻区 3 常驻展示（含清理范围说明） |
| `process_warning` | 告警条（进程数 / 并发任务数 / 任务时长超阈值），琥珀色、不打断执行 |
| `process_count_error` | 计数失败时的明确提示，不用 0 冒充 |
| `detached_history` | 启动时展示上次留下的 detached 清单，逐条标「未经核实」；终止入口须回显身份核对结果 |

## 6. 关键交互（都是真实高频动作，稿里没有后面就要返工）

1. **`@` 引用文件** — 输入框里打 `@src/main.go` 直接把文件带进对话，要有路径自动补全。用户不该被迫描述"就是那个处理登录的文件"。
2. **粘贴大段日志** — 最高频动作之一：贴一坨报错问"这什么意思"。要能贴、自动折叠成附件、不撑爆输入框。
3. **中断当前轮** — 一个明确的停止按钮（对应 Ctrl-C）。中断后能接着说，不是重开会话。
4. **展开工具结果 / 复制路径** — 一下点开，路径与命令可复制。
5. **回滚** — 从检查点列表触发，确认前回显具体目标。
6. **切换工作区 / 恢复会话** — 恢复会话默认回到它原来的工作区；要迁移就新建会话，界面上不给"混用"的可能。恢复后通过会话消息分页接口拉取历史对话渲染进任务流（工具记录同样可折叠/展开，与实时产生的一致）。

## 7. 视觉与技术约束（**硬约束，先读再动笔**）

### 运行环境

- **浏览器只可能是 Chrome 109 或 Firefox 115 ESR**（Win7 上最后可用的版本）。不要用需要更新内核的效果。
- **设计基线分辨率 1366×768**（老笔记本是主力机型），1920×1080 只需给出拉伸规则。
- **老机器 + 老显卡**：不要毛玻璃、大面积阴影、持续动画。动效只用于回应用户操作，≤150ms。
- **字体只能用 Win7 自带的**：正文中文 **微软雅黑**，等宽 **Consolas**。**不要 Inter、不要 Noto、不要 SF**——内网无 CDN，内嵌中文字体会让单 exe 体积失控。
- **界面语言只做简体中文**。内网 Windows 只有简中和英文两种。技术术语（tool、checkpoint、skill、token）保留英文原词，不硬译。
- **启动路径**：桌面快捷方式 → `pulse7 serve`（仅此模式启动本地监听并自动打开页面；直接双击 exe 是 CLI，保持现状）。

### 视觉方向

**把它当值班台，不要当聊天软件。** 内容本质是一条带证据的操作记录，不是对话。所以：

- **不要头像、不要气泡、不要左右分栏对话。** 用单栏时间轴，左侧一条细轨道线标示轮次归属。
- **不要圆角卡片堆叠 + 统一柔和阴影**——那是通用 SaaS 模板的样子，在这个产品上既不好看也不好用。用 1px 细边框与背景色块区分层级。
- **等宽字体承担全部"机器原文"**：路径、命令、退出码、字节数、token 数、commit 哈希。正文用中文正常字体。**这条分工是信息设计，不是装饰**——用户要一眼分清"系统在跟我说话"和"这是机器原样输出"。
- **颜色只承担状态，不做装饰**。建议一套功能色而非一个品牌强调色：运行中（蓝）、成功（绿）、失败（红）、等待与告警（琥珀）、系统自动处理如截断/压缩/放行（灰）。**不要渐变。** Win7 老屏色准差，正文对比度按 7:1 起。
- 底色用中性冷灰纸面，不要暖米色 + 衬线标题那一套。

### 文案

- 句子式中文，不用全大写标签，不用"处理中…"这类不含信息的占位。
- 错误说清三件事：发生了什么、影响什么、下一步做什么。不道歉、不含糊。
- 同一个动作从按钮到结果用同一个词：按钮写「回滚」，结果就写「已回滚」。

## 10. 设计稿验收（**这十个问题答不上来就还没画完**）

1. 端点很慢，模型 40 秒没返回，屏幕上是什么样子？用户凭什么判断不是卡死？
2. 上下文还剩多少，在哪看？"这是估算值"这件事怎么表达出来？
3. agent 往工作区外写了文件，用户在哪、在什么时候、看到几次？
4. 用户想停下当前这轮，点哪里？停下之后能接着说吗？
5. 有个后台任务在跑，用户切去看别的会话，怎么知道它还活着？
6. 回滚之前，用户看到的目标是什么？看不到序号、时间和 commit 就是不合格。
7. 同事第一次双击桌面快捷方式（pulse7 serve），头三步分别是什么？
8. 5000 行日志粘进输入框会发生什么？
9. 工具结果很长，默认是折叠还是展开？用户怎么定位到具体那个文件？
10. 端点连不上、或者 token 失效了，界面说什么？

这个产品的用户不需要被保护，需要被告知。**界面上每一处"替用户省事"的设计，都要先确认它没有同时把事实藏起来。**
