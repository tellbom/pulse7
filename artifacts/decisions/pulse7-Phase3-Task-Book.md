## 0.5 判断准则（歧义时按此判断方向；仍需新增本文件未列出的行为则**停止并报告**）

1. **高自治**：不建造二次猜测模型推理的机制（计划器、验证器、状态机、强制流程）。代码负责路径、持久化、生命周期与协议完整性；下一步做什么由模型判断。
2. **低摩擦**：不新增确认门、不新增必须由用户回答才能继续的提示。
3. **强可见**：凡是系统替用户做了处理——截断、压缩、丢弃、放行、降级、重试、收割——都必须留下用户事后可查的痕迹。**可见性不打断执行、成本为零。**
4. **保留低成本事实校验**：路径解析、文件新鲜度、流终止判定、编码判定，全部保留。
5. **错误可恢复优先于错误静默**：能走既有恢复路径的走恢复路径，不能恢复的明确报错。**任何情况下都不许静默继续。**
6. **不对自己不知道的事实装作知道**：估算标注为估算，未验证写未验证，错误来源不许张冠李戴，未实现的能力不许写成已交付。

## C1 —— 接口契约文档（**首要交付物**）

产出 `artifacts/api-contract.md`（在现有文件上更新，不新建）。

### C1.0 先做：逐条核实实现状态

**契约的职责是照着代码记事实，不是照着计划记愿望。**

以下能力在此前多轮中或已实现、或部分实现、或仅有规格。**逐项读源码核实**，在契约中明确标注三种状态之一：**已实现** / **部分实现（说明差在哪）** / **未实现（规格已定，非目标能力）**。

- 后台任务（B4）：`shell` 的 `background` 参数、任务表、`task_output`、`task_kill`、REPL `/tasks`、输出硬上限 50MB、并发数与时长告警、四条退出路径的收割、`detached` 选项与退出时清单；
- 会话级 JobObject（进程模型决策一）：会话级 Job、前台超时仍击杀子树、Job 分配失败的受限模式、进程数告警阈值；
- **F5 主动推送**：后台新输出当前是"拉取的副作用"——只有调用 `task_output` 且读到字节才发事件。**这是现状说明，不是目标能力**，必须如实标注；
- 权限档位、工作区外写的三处可见、hard link 的能力性拒绝、`.git` 保护；
- 上下文：截断标记、紧急压缩重试、`context_state` 的估算性质。

**不得把规格文档里的描述当作已实现写进契约。**

### C1.1 数据模型

至少覆盖：

- 会话：`uuid` / `parentUuid` / `timestamp` / `sessionId` / `cwd` / `version` / `role` / `content` / `tool_calls`（决策四 4.1 已定死，**不得新增顶层字段**）；
- 上下文状态：已用 / 预算 / 剩余百分比，**必须标明为估算值**；
- 后台任务：task_id、命令、状态（运行中 / 已结束 / 被终止 / 输出超限截断）、启动时间、运行时长、输出文件大小、退出码；
- 会话进程概况：会话 Job 内进程数、是否超告警阈值；
- detached 进程清单：命令、PID、启动时间；
- 权限档位与规则的当前生效值；
- checkpoint：序号、时间、commit、创建方式（自动 / 模型主动）、**`dirty-files` 及其含义（工作区相对 HEAD 的变更文件数，非本次任务改动数）**；
- 工作区外写入：requested path、resolved path、checkpoint 覆盖标志（false）；
- 监听状态：地址、端口、token 有效性。

### C1.2 操作接口

至少覆盖：发起任务、中断、回答提问（`need_answer` 的应答入口）、后台任务列表 / 拉取输出（支持增量 offset）/ 终止、checkpoint 列表与回滚、权限档位切换（含即时生效说明）、配置读取与**连接测试**、工作区选择、会话列表与恢复。

> 复核已指出：`resultRef` 无解析入口、确认仅 stdin、中断仅 Ctrl-C、配置连接测试与 checkpoint 列表缺失，**都属于必须补齐的接入面**。

### C1.3 事件流

沿用已定名称，**不自创**：`session_init` / `assistant_delta` / `tool_call` / `tool_result` / `permission_request` / `permission_response` / `context_state` / `compaction` / `skill_loaded` / `background_task` / `heartbeat` / `turn_result`。

本轮新增、必须一并记入：

- **F2 的 attempt 语义**：attempt 序号、start / complete / discard，以及**消费者的丢弃规则**（哪些已发出的 delta 应当作废）；
- **工作区外写入事件**；
- **hard link 的能力性拒绝**：前端要能区分"权限不足"与"系统无法确定影响面"，两者给用户的下一步动作不同；
- **上下文截断**：原始字节数、丢弃字节数、保留与丢弃的组；
- 后台任务启动 / 新输出 / 结束、告警触发（进程数 / 并发任务数 / 任务时长）、detached 进程创建（含"将在退出后继续运行"的标注）。

### C1.4 明确写进契约的三件事

1. **前端对后台任务与进程概况的展示应当常驻可见**（侧边栏或状态栏），不埋在对话流里；
2. **CLI 与 GUI 共用同一份事件 schema**，两个出口：SSE 给 GUI，NDJSON（`--output-format stream-json`）给自动化；
3. **已知限制**：最近一组工具结果在最小化之后仍可能超出预算（R2 窄配置实测：保底 4182 字节 > 可用 3424 字节），此时按规格明确报错而非静默继续；**默认 48000 预算下随仓库规模增大同样可能触发，阈值未知。**

把"产生事件"与"渲染成人类可读输出"分开，使同一份事件既能走 CLI 渲染，也能走 SSE 推送。

- 已知差异：默认轮次上限 30 vs 100 先于本轮存在，保持 NOT MET 的如实记录。

## C3 —— HTTP + SSE 层

### 安全约束（**逐条不可放宽**）

- **仅绑定 `127.0.0.1`，不得绑 `0.0.0.0`**；
- **随机端口**，不使用固定端口；
- 启动时生成**一次性 token**，前端必须携带才能访问；
- **进程退出即关闭监听**；
- `doctor` 与界面上明示监听地址、端口与状态；
- **CLI 模式完全不受影响**：不启动 HTTP 时不监听任何端口。

### 实现约束

- **Go 标准库实现**，不引入框架与路由库；
- 事件流用 **SSE**，与现有 LLM 流式处理同构；
- 按 C1 冻结的契约实现接口与事件，**契约之外的接口一律不加**；
- 长操作必须有活性证据（`heartbeat` 已定），前端要能区分"等待中 / 工具未返回 / 已中断"，**不得伪造进度**。

### 关于 F5 主动推送

- 若 C1 核实后 F5 仍未实现：**本阶段实现由后端观察并推送后台输出变化与告警**，不再要求前端轮询；
- 实现方式用轻量文件观察或计时器即可，**不得引入 Claude Code 的任务架构**；
- 若实现需要超出上述范围，**停止并报告**。
