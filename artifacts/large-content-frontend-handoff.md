# 大内容后端接口：前端待接入

2026-09-13。本文是接入说明，不是浏览器验收结果。本轮未修改前端。

- 历史消息可能包含 `largeContent` 字典，键为 content、reasoning、toolcall-N，值为不透明的 lc1 引用。原有字段为预览/投影，不能标成完整原文，也不要把历史投影参数重新执行。
- 工具结果接口保留 id/result，并增加 offset、nextOffset、totalBytes、hasMore、contentRef。offset/limit 为字节，默认 32768、最大 262144。下一页必须使用服务端 nextOffset，不能用 JavaScript 字符数计算偏移。
- 沿用现有工具结果路由的 ref 参数，可传原有工具引用或 lc1 引用；指定合法 sessionId。对正文、推理、大参数都可以按引用展开。不要解析或自行构造 lc1 内部格式。
- 消息分页沿用 offset/nextOffset/hasMore，这里的 offset 为消息条数，与附件字节偏移不同。
- 会话列表成功响应中的 errors 需逐项展示警告，健康 sessions 仍可选择；不能将单个坏文件提示覆盖成整个列表空白。
- 附件缺失、损坏、非法游标等错误应可见，保留已有预览并提供重试入口，不能把失败显示为成功或自动重复执行工具。
- 刷新历史时使用持久化 toolOutcome 判断成功/失败，不以工具结果是否存在判成功；推理和工具调用内容可能只是预览，应提供按需查看原文入口。
- 使用逐页追加/虚拟列表，避免把所有附件自动拉取并拼成巨型 DOM。会话备份需包含旁边的 `.jsonl.content` 目录。
